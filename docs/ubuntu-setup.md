# Running Bartop Arcade on Ubuntu

Step-by-step guide for putting the arcade on an Ubuntu computer driving the
17 inch landscape touchscreen (1920 × 1080). Tested target: Ubuntu 22.04 /
24.04 desktop (GNOME). Other Linux desktops work too; only the auto-start and
screen-blanking steps differ.

---

## First: this is not a DOSBox game

DOSBox runs old **MS-DOS programs** (`.exe` / `.com` files from the 1990s).
Bartop Arcade is a **web page** — HTML + JavaScript drawn on a `<canvas>` —
so it runs in a **web browser** (Chromium, Chrome or Firefox), not in DOSBox.
There is nothing to install or compile for it; you only need:

1. The files from this repository.
2. `python3` (to run a tiny local web server — already on Ubuntu).
3. A browser (Chromium recommended).

> If you also want real old DOS games on the same bartop, DOSBox can be
> installed alongside (`sudo apt install dosbox`) — but that is a separate
> project and does not affect this arcade.

### Why not just double-click `index.html`?

The game loads its code as JavaScript *modules*. Browsers block modules on
pages opened straight from disk (`file://…`), so you get a **black screen**.
The game must be opened through a web server (`http://127.0.0.1:…`).
`scripts/start-arcade.sh` handles that for you.

## Step 1 — Install what's needed

Open **Terminal** (press `Ctrl` + `Alt` + `T`) and paste:

```bash
sudo apt update
sudo apt install -y git python3 curl
sudo snap install chromium
```

(Firefox already comes with Ubuntu and also works, but Chromium's kiosk mode
is more reliable on touchscreens.)

## Step 2 — Download the game

```bash
cd ~
git clone https://github.com/goodrica/bartop-arcade.git
cd bartop-arcade
```

If the repository is private, GitHub will ask you to log in. Alternatively,
download the ZIP from GitHub (**Code → Download ZIP**) and unzip it into your
home folder as `bartop-arcade`.

To get updates later:

```bash
cd ~/bartop-arcade
git pull
```

## Step 3 — Try it in a window

```bash
cd ~/bartop-arcade
./scripts/start-arcade.sh --window
```

You should see the neon **BARTOP ARCADE** menu with a **Photo Hunt** card.
Tap it and play a round. Close the window when done — the helper web server
stops automatically.

## Step 4 — Run it full screen (kiosk mode)

```bash
./scripts/start-arcade.sh
```

This fills the screen with no browser toolbars. To exit, press `Alt` + `F4`
(plug in a keyboard if needed).

## Step 5 — Start automatically when the computer boots

```bash
./scripts/install-ubuntu-autostart.sh
```

This:

- starts the arcade every time this user logs in,
- adds a **Bartop Arcade** icon to the app menu,
- turns off screen blanking, the lock screen and idle sleep.

Then turn on **automatic login** so no password screen appears at boot:
**Settings → Users → Unlock → Automatic Login: On**.

Reboot to check. To undo everything:

```bash
./scripts/install-ubuntu-autostart.sh --remove
```

## Setting up the touchscreen

1. Plug in the touchscreen's **HDMI/DisplayPort** *and* its **USB** cable
   (the USB cable carries the touch signal).
2. **Settings → Displays**: resolution **1920 × 1080**, orientation
   **Landscape**, scale **100 %**.
3. Touch a corner of the screen — the pointer should land under your finger.
   If touches land on the wrong spot or are rotated:
   - With two monitors attached, touch may be mapped to the wrong one.
     Unplug the other monitor, or (on X11) run
     `xinput map-to-output "<touch device name>" HDMI-1`
     (list names with `xinput list` and outputs with `xrandr`).
   - On Ubuntu's default Wayland session, touch mapping follows the display
     settings; if it is still wrong, pick **Ubuntu on Xorg** on the login
     screen (gear icon) and use the `xinput` command above.
4. Inside the game, taps are mapped from the screen to the game's own
   1920 × 1080 layout automatically — no calibration is needed in the game.

## Sound

Sounds are generated by the browser (no audio files). The kiosk launcher lets
sound play straight away. If you hear nothing:

- **Settings → Sound**: pick the right output (HDMI for monitor speakers) and
  check the volume.
- Tap the screen once — some browsers only allow sound after a first touch.

## Troubleshooting

| Problem | Fix |
|---|---|
| Black screen | You opened `index.html` directly. Use `./scripts/start-arcade.sh`. |
| `Permission denied` running a script | `chmod +x scripts/*.sh` |
| `port 8080` / server did not start | Another program uses that port: `ARCADE_PORT=8090 ./scripts/start-arcade.sh` |
| Wrong browser opens | Choose one: `ARCADE_BROWSER=firefox ./scripts/start-arcade.sh` |
| Kiosk mode opens a normal window | Close every other window of that browser first (Firefox), or use Chromium. |
| Old version still showing after `git pull` | Close the arcade and start it again; in a window press `Ctrl` + `Shift` + `R`. |
| Screen goes dark after a few minutes | Rerun `./scripts/install-ubuntu-autostart.sh`, or turn off **Screen Blank** in Settings → Power. |
| "Chromium didn't shut down correctly" bar | Harmless; the launcher uses flags that normally hide it. |

## For agents and developers

Pick-up notes so the next person (human or AI) can continue without asking.

**Files involved**

| File | Purpose |
|---|---|
| `scripts/start-arcade.sh` | Starts `python3 -m http.server` bound to `127.0.0.1:$ARCADE_PORT` (default 8080), launches the first browser found (`chromium`, `chromium-browser`, `google-chrome`, `google-chrome-stable`, `firefox`, or `$ARCADE_BROWSER`) in kiosk mode (`--window` for a normal window), and kills the server when the browser exits. Reuses a server already answering on the port. |
| `scripts/install-ubuntu-autostart.sh` | Writes `~/.config/autostart/bartop-arcade.desktop` and `~/.local/share/applications/bartop-arcade.desktop` pointing at `start-arcade.sh`; sets GNOME `idle-delay 0`, `lock-enabled false`, `sleep-inactive-ac-type nothing`. `--remove` undoes all of it. Per-user, no sudo. |
| `docs/ubuntu-setup.md` | This guide. |

**Design decisions**

- A server is required because `index.html` loads `type="module"` scripts,
  which Chromium blocks from `file://` (verified: CORS error on
  `js/engine.js`). Don't reintroduce "double-click index.html" instructions.
- Chromium gets a dedicated `--user-data-dir` so kiosk flags apply even if
  the user's normal Chromium is open. Snap Chromium can only write inside
  `~/snap/chromium/`, so the profile lives at
  `~/snap/chromium/common/bartop-arcade-profile` for the snap and
  `~/.local/share/bartop-arcade/browser-profile` otherwise.
- `--autoplay-policy=no-user-gesture-required` lets `AudioManager`
  (`js/audio.js`) produce sound without a first tap.
- The server binds to `127.0.0.1` only; the arcade is not exposed on the
  network.
- The game itself was not modified for Ubuntu; it is plain browser code.
  `scripts/serve.py` is the *Photo Hunt editing* server (port 8091, needs
  numpy/Pillow) — not needed to play.

**How this was verified (2026-09-29, cloud container, no physical screen)**

- `start-arcade.sh` run with a stand-in browser wrapping headless Chromium at
  1920 × 1080: server started, kiosk flags passed, menu rendered correctly,
  server stopped after the browser exited.
- `index.html` over `file://` confirmed to fail with a module CORS error.
- `install-ubuntu-autostart.sh` and `--remove` run against a throwaway
  `$HOME`; `.desktop` files written and removed. GNOME `gsettings` schemas were
  absent in the container, so the screen-blanking step was only exercised on
  its warning path.

**Not yet verified on real hardware** — next agent/human should check on the
actual Ubuntu bartop:

1. Snap Chromium accepts the `~/snap/chromium/common/...` profile path.
2. GNOME autostart launches the arcade after automatic login.
3. Touch input lands correctly on the 17" screen (Wayland and Xorg).
4. Sound plays through the monitor/speakers without a first tap.
5. Screen never blanks during a multi-hour idle period.
